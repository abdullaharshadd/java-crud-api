## Components that could not be automatically migrated

### `JpaRepository inherited CRUD methods` in `src/main/java/com/smartContact/repository/UserDao.java`
**Reason:** These are auto-generated by Spring at runtime with no source code; there is no direct Go equivalent that generates methods from an interface signature.
**Suggestion:** Manually implement needed CRUD methods on a Go repository struct using sqlx or gorm. With gorm, generic CRUD (Create/First/Find/Save/Delete) covers most inherited methods; with sqlx write explicit SQL per method.

### `findByName (query derivation)` in `src/main/java/com/smartContact/repository/UserDao.java`
**Reason:** The query is derived implicitly from the method name by Spring; no explicit SQL exists in source.
**Suggestion:** Write explicit SQL: `SELECT ... FROM users WHERE name = $1` (sqlx) or `db.Where("name = ?", name).First(&user)` (gorm). Return (User, error) and handle not-found explicitly.

### `@Valid bean validation` in `src/main/java/com/smartContact/Controller/UserController.java`
**Reason:** Relies on annotation-driven JSR-380 validation on the User model, which has no direct Go equivalent.
**Suggestion:** Reimplement validation explicitly using go-playground/validator struct tags or manual validation in the handler.

### `UserNotFoundException exception-to-HTTP mapping` in `src/main/java/com/smartContact/Controller/UserController.java`
**Reason:** Status code mapping for the thrown checked exception is defined by a separate @ControllerAdvice/@ExceptionHandler not present in this file.
**Suggestion:** Locate the global exception handler and translate error-to-status logic into explicit error returns/HTTP status writes in Go handlers.

### `setUp (Mockito.when on @Autowired real bean)` in `src/test/java/com/smartContact/service/UserServiceImpTest.java`
**Reason:** Mockito.when() is being applied to a real Spring-managed bean, not a mock, so the stubbing behavior does not exist in any target language and reflects a bug in the original test rather than translatable logic.
**Suggestion:** Manually rewrite: define a UserDao interface, create a mock (testify/mock or gomock), stub the lookup method, and inject the mock into UserServiceImp via constructor injection. Do not attempt a literal translation.

### `@BeforeAll setUp lifecycle` in `src/test/java/com/smartContact/service/UserServiceImpTest.java`
**Reason:** JUnit 5 @BeforeAll semantics (static vs PER_CLASS instance lifecycle) have no direct Go equivalent and the current usage is likely non-functional.
**Suggestion:** In Go, perform setup inside the test function itself or use TestMain for package-level setup; wire mocks per-test for isolation.

### `SmartContactApplicationTests (@SpringBootTest)` in `src/test/java/com/smartContact/SmartContactApplicationTests.java`
**Reason:** The @SpringBootTest annotation relies on Spring's ApplicationContext bootstrapping mechanism which has no direct equivalent outside the Spring ecosystem.
**Suggestion:** Do not port literally. Write a native smoke test in the target framework that boots the application/container and asserts successful startup (e.g., a health-check or app-init test).

### `spring.jpa.hibernate.ddl-auto=update` in `src/main/resources/application.properties`
**Reason:** This is Hibernate-specific automatic schema synchronization behavior with no universal cross-framework equivalent; behavior depends on the ORM's entity introspection.
**Suggestion:** Replace with an explicit database migration tool in the target (Flyway/Liquibase, or Alembic/Prisma/TypeORM migrations) rather than relying on runtime auto-update.

### `spring.jpa.properties.hibernate.dialect` in `src/main/resources/application.properties`
**Reason:** Hibernate dialect is a Java ORM internal concept that does not exist outside Hibernate/JPA.
**Suggestion:** Drop this property; the target's MySQL driver/ORM handles dialect automatically. Ensure the target ORM is configured for MySQL 8.

### `lombok` in `pom.xml`
**Reason:** Lombok is a Java-specific compile-time annotation processor that generates getters, setters, constructors, builders, and equals/hashCode. It has no direct equivalent in most target languages and must be handled where those annotations are used in source files.
**Suggestion:** When migrating entity/model classes, expand Lombok-generated members explicitly (or use the target language's native idioms like Python dataclasses, TypeScript classes, Go structs with generated code, Kotlin data classes).

### `pom.xml (whole file)` in `pom.xml`
**Reason:** A Maven build descriptor cannot be automatically translated into another language's build/dependency system; dependency semantics and transitive resolution differ.
**Suggestion:** Manually author the target's dependency manifest, mapping each Spring starter to its functional equivalent and pinning explicit versions.

### `maven-wrapper.properties` in `.mvn/wrapper/maven-wrapper.properties`
**Reason:** This is Maven-specific build tooling with no analog outside the Maven ecosystem; it defines no application logic to translate.
**Suggestion:** Keep in source form if the project stays on Maven, or replace with the target ecosystem's build/dependency management configuration (e.g., package.json, go.mod, pyproject.toml). Do not attempt code-level migration.
